LithLingo Documentation

Complete technical reference for the Lithuanian language learning platform.

🇱🇹 What is LithLingo?

LithLingo is a full-stack Lithuanian language learning platform that gamifies learning through interactive lessons, exercises, listening activities, streak tracking, XP rewards, and daily quests.

Frontend
React + Vite
Backend
Django REST
Database
PostgreSQL
Cache
Redis

Frontend Stack

React 19.2.4 Vite 8.0.4 React Router 7.14 TailwindCSS 4.2 Axios React Query Lottie React DiceBear Avatars Lucide Icons

Backend Stack

Django 6.0.3 DRF 3.17.1 PostgreSQL Redis Simple JWT gTTS (Audio) Pillow

Target Users

  • ✓ Lithuanian language learners (beginner → intermediate)
  • ✓ Students who benefit from gamified, structured learning
  • ✓ Learners who need audio pronunciation guides
  • ✓ Users building daily habits via streak tracking

cd backend

🔐 Authentication Flow

Registration

1
User fills form — email, password, name, gender
2
POST /api/auth/register/ — backend validates email uniqueness + password complexity
3
Creates User with is_verified=False, generates verification_token (UUID) + avatar_seed
4
Auto-creates UserLessonProgress for first lesson of each unit
5
Sends verification email → user clicks link → GET /api/auth/verify-email/{token}
6
Backend sets is_verified=True → frontend redirects to login

Login & JWT Token Flow

1
POST /api/auth/login/ with email + password
2
Backend validates: user exists, password correct, is_active, is_verified
3
Generates access token (15 min) + refresh token (7 days) → set as HttpOnly cookies
4
Frontend stores user data in AuthContext

Automatic Token Refresh

1
API request fails with 401 (access token expired)
2
Axios interceptor catches 401 → auto POST /api/auth/token/refresh/
3
Backend validates refresh token → issues new access + refresh (old token blacklisted in Redis)
4
Interceptor retries original request with new token. If refresh fails → redirect to /login
⚠️
ROTATE_REFRESH_TOKENS = True — every refresh generates a new refresh token and blacklists the old one. This prevents token reuse attacks.

Authentication Endpoints

✨ Features

Lesson Structure

Lessons are organized in a hierarchy: Section → Unit → Lesson. Each lesson has 5 phases:

1
Grammar
Rule explanations with examples
2
Vocabulary
Words with audio, translation, images
3
Listening
Audio clip + comprehension MCQs
4
Exercises
Multiple choice, fill-blank, matching
5
Completion
XP reward + next lesson unlock

Exercise Types

TypeUIAnswer Logic
multiple_choice2×2 button grid, select then CheckCase-insensitive string match
fill_blankText input fieldCase-insensitive string match
matchingDrag-and-drop two columnsValidates against MatchingPair model
listeningAudio player + MCQ optionsListeningOption.is_correct flag

Lesson Progression

→
First lesson of first unit: auto-unlocked on registration
→
User completes lesson → completeLesson() called
→
Backend unlocks order + 1 in same unit, or first lesson of next unit
→
User earns XP (xp_reward on lesson) + streak updated

Streak System

# streak_service.py logic
if last_active == today:     skip (already counted today)
elif last_active == yesterday: current_streak += 1
else:                         current_streak = 1  # reset

update longest_streak if current > longest
set last_active = today

🗂️ State Management

AuthContext

Located at src/context/AuthContext.jsx. Wraps the entire app.

// What it provides:
const { 
  user,          // { id, email, first_name, last_name, gender, bio, avatar_seed, date_joined }
  isLoading,     // true while checking auth on mount
  login,         // (email, password) → sets user
  logout,        // clears user + cookies
  updateUser,    // updates user fields locally after PATCH
} = useAuth();

StatsContext

Located at src/context/StatsContext.jsx. Provides streak and progress data to the right panel.

// What it provides:
const {
  stats,         // { current_streak, longest_streak, completed_lessons, progress_percentage, daily_goal, daily_completed }
  refreshStats,  // call after completing a lesson
} = useStats();

Local State

Each exercise component manages its own answer/feedback state. localStorage is used only for cookie consent (cookie_consent key).

✅
React Query handles server state caching automatically. No manual cache invalidation needed for most data fetches.

🔑 Environment Variables

🚨
Never commit .env files. Always use .env.example with empty values as the committed template.

Frontend — frontend/.env

VITE_API_URL
Backend API base URL. Dev: http://localhost:8000/api — Production: your deployed URL. Required.

Backend — backend/.env

DB_NAME / DB_USER / DB_PASSWORD / DB_HOST / DB_PORT
PostgreSQL connection details. Required.
SECRET_KEY
Django secret key. Generate with python -c "import secrets; print(secrets.token_hex(50))". Required.
DEBUG
True for development, must be False in production.
ALLOWED_HOSTS
Comma-separated hostnames. Dev: localhost,127.0.0.1.
JWT_ALGORITHM
HS256 — signing algorithm for JWT tokens.
EMAIL_HOST / EMAIL_PORT / USER_EMAIL / EMAIL_PASSWORD
SMTP config for verification emails. Use Gmail App Password.
CORS_ALLOWED_ORIGINS / CSRF_TRUSTED_ORIGINS
Frontend URLs allowed to call the API. Dev: http://localhost:5173.
REDIS_URL
Redis connection. Dev: redis://127.0.0.1:6379/1. Used for JWT blacklist + caching.
MEDIA_ROOT
Absolute path to media directory for audio/image storage.

🚀 Deployment

Frontend Build

npm run build  # Creates optimized output in frontend/dist/

Upload dist/ to any static host: Vercel, Netlify, or Cloudflare Pages. Set VITE_API_URL to your production API URL.

Backend Checklist

  • ✓ Set DEBUG=False in production .env
  • ✓ Set strong SECRET_KEY (use Python secrets module)
  • ✓ Add production domain to ALLOWED_HOSTS and CORS_ALLOWED_ORIGINS
  • ✓ Run python manage.py collectstatic --noinput
  • ✓ Use HTTPS only — set Secure flag on cookies
  • ✓ Use PostgreSQL (not SQLite)
  • ✓ Move media/ to S3 or similar cloud storage
